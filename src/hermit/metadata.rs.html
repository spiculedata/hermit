48/// hermit record/replay version.
49// NB: Increase the version number when there are breaking changes, i.e.:
50// when new syscalls or event schemas are added.
51//
52// AUTONOMOUS-BOT-IMPLEMENTED
53// TODO-HUMAN-REVIEW(#2373)
54// 0x10b -> 0x10c: flock(2) stopped being a Detcore no-op and now reaches
55// `record_or_replay`, so a post-fix run emits a `Return` event per flock call.
56// Replay re-issues calls for materialized descriptors and fails closed when it
57// cannot reproduce the lock side effect. A 0x10b recording contains NO flock
58// event at all -- the old handler returned Ok(0) before ever reaching the
59// recorder, even though flock was already classified Determinized -- so
60// replaying one under this build would read the next thread event for every
61// flock and desynchronize the stream. The version gate must refuse it.
62//
63// TODO-HUMAN-REVIEW(#2370)
64// 0x10d -> 0x10e: record/replay now carries successful exec image/path state and
65// an explicit ppoll timeout-pointer shape. Older readers cannot interpret those
66// events without desynchronizing the stream, so the format advances once.
67//
68// TODO-HUMAN-REVIEW(#2272)
69// 0x10c -> 0x10d: `Ppoll` becomes its OWN event rather than sharing `Poll`'s,
70// because ppoll additionally copies out a timeout and must preserve it on
71// EINTR and on a partial EFAULT copy-out; and `Poll` itself now records the
72// partial `revents` copy-out an error return leaves behind. The recorded
73// stream therefore carries a different event shape for both syscalls.
74//
75// ONE increment covers BOTH halves deliberately. This branch bumped twice --
76// once per format change -- but a reader either understands the new stream or
77// it does not, so what matters is that the version differs from every stream
78// a different shape was written under. Landing two increments would imply a
79// 0x10d recording exists that this build can read and it cannot: no build
80// ever wrote one.
81//
82// ⚠️ THIS BUMP IS WHY THE REBASE COULD NOT SIMPLY TAKE EITHER SIDE. This
83// change was authored against 0x10a and bumped to 0x10b; main has since gone
84// to 0x10c for the unrelated flock work. Keeping the branch's 0x10b would
85// move the version BACKWARDS and let a 0x10c flock recording be replayed by a
86// build whose ppoll events have a different shape. Keeping main's 0x10c
87// unchanged would be worse: the format would change with no bump at all, so a
88// recording made here would claim 0x10c while containing a `Ppoll` event the
89// 0x10c reader does not know -- exactly the desynchronization the paragraph
90// above exists to prevent. The version must go FORWARD once more.
91//
92// AUTONOMOUS-BOT-IMPLEMENTED
93// TODO-HUMAN-REVIEW(#2407)
94// 0x10e -> 0x10f: pidfd_getfd(2) is now explicitly subscribed and recorded.
95// Earlier builds let the syscall bypass the recorder, so a successful call
96// changed the guest descriptor table without a corresponding stream event.
97// The replayer now consumes one exact pidfd_getfd event and reissues the
98// syscall to reproduce the kernel side effect; accepting a 0x10e stream would
99// therefore consume the next event at every pidfd_getfd call.
100//
101// 0x10f -> 0x110: metadata now carries the recording namespace's proven
102// Hermit-owned mount IDs. Detcore applies that map after both the recorder's
103// raw read and the replayer's ReadV2 copyout. An older recording has no map and
104// would replay different guest-visible mountinfo bytes under this sanitizer,
105// so accepting it would violate replay fidelity even though the event enum did
106// not change.
107//
108// 0x110 -> 0x111: metadata now also carries the recording namespace's full
109// raw mount-ID order. That makes fdinfo's mnt_id use the same canonical identity
110// as mountinfo during replay instead of consulting the unrelated replay
111// namespace or collapsing all descriptors to one mount.
112// 0x111 -> 0x113: fdinfo mount identities are now keyed by each observed raw
113// mount ID rather than broad descriptor classes. Metadata carries only the
114// completed namespace's mountinfo row/parent order; pseudo-filesystem IDs that
115// are absent from mountinfo are allocated afterward in deterministic guest
116// observation order. Replay must rebuild that mapping from recording-time raw
117// bytes, or pidfs/nsfs/anon_inodefs can be collapsed or rejected. The draft
118// 0x112 format was never shipped.
119//
120// 0x113 -> 0x114: recordings persist the completed guest's mountinfo order and
121// unlisted fdinfo mount-ID order, and event streams use stable recording-local
122// thread IDs rather than host PID allocation. An older reader cannot rebuild
123// either mapping reliably for a plain public record API recording.
124//
125// 0x114 -> 0x115: event stream filenames now encode deterministic process-tree
126// pedigrees instead of process-local allocation order. Older readers look for
127// integer filenames and cannot replay a recording containing child streams.
128//
129// 0x115 -> 0x116: event stream filenames are fixed-size SHA-256 names and each
130// data/debug stream begins with its complete process-tree identity. Older
131// readers cannot skip or validate these headers.
132// 0x116 -> 0x119: nonpositioned random-device readv now uses Detcore's
133// shared canonical cursor and no longer emits or consumes recorder ReadvV2
134// events. Old event streams cannot be replayed under this routing.
135// 0x117 and 0x118 identify incompatible retained RNG, clock, and network
136// recordings from parallel development; do not reinterpret those identities.
137// 0x119 -> 0x11a: random-device preadv/preadv2 now use Detcore's canonical
138// generator, including the shared cursor for preadv2(-1). They no longer emit
139// or consume ReadvV2 events; accepting an older recording would desynchronize
140// the event stream and replace its recorded random bytes.
141// Early rejection of invalid negative offsets also stops emitting ReadvV2
142// error events for non-random descriptors.
143// 0x11a -> 0x11b: sysinfo uptime rounds exact elapsed logical time up, removing
144// dependence on the calendar epoch's fraction. Detcore recomputes sysinfo during
145// recording/replay, even with virtualize_time=false; replaying an older stream
146// under the new projection could change guest control flow and event consumption.
147// Sysinfo remains determinized rather than gaining a recorded event.
148// 0x11b -> 0x11c: /proc/uptime renders the floor of exact elapsed logical time
149// instead of the difference of the separately truncated clock and epoch, so a
150// fractional epoch no longer moves it (or /proc/stat's idle ticks derived from
151// it) by one second. /proc/stat btime is now derived from the fixed boot
152// instant rather than from the clock minus uptime. Detcore recomputes these
153// fields over the recorded procfs bytes during recording and replay, so an older
154// stream replayed under the new projection could show the guest different bytes.
155// 0x11c -> 0x11d: with time not virtualized, which is always the case for
156// record/replay, detcore passes clock reads to record/replay instead of refusing
157// them. Streams now carry Timespec and Timeofday events for clock_gettime,
158// gettimeofday and time, and clock_getres gains a recorder event (Timespec, or
159// Return for a NULL `res`). An older reader would desynchronize on these events.
160// 0x11d -> 0x11e: guest-semantic madvise advice, which detcore used to refuse
161// with ENOSYS, now reaches the recorder and replayer and emits a Madvise event.
162// 0x11e -> 0x11f: faccessat, faccessat2, chdir, getcwd and the legacy path
163// mutations (rename, link, symlink, chmod, chown, lchown, mknod, rmdir) are
164// recorded instead of running live. A successful chdir or fchdir carries a
165// Bytes event naming the directory it entered. An older reader would
166// desynchronize on these events.
167// 0x11f -> 0x120: descriptor syncs and metadata changes (fsync, fdatasync,
168// syncfs, fchmod, fchown, fsetxattr, fremovexattr) record a Return event, the
169// xattr queries (getxattr, lgetxattr, fgetxattr and the listxattr family)
170// record a Bytes event (Return for a zero-size query), and zero-count read and
171// pread64 calls are recorded instead of running live. An older reader would
172// desynchronize on these events.
173// 0x120 -> 0x121: splice and tee refuse with EINVAL instead of ENOSYS; vmsplice
174// keeps ENOSYS. Record and replay always fail closed, and Detcore computes this
175// refusal itself rather than recording it, so replay recomputes the errno. The
176// guest can branch on it: GNU grep falls back to read/write on EINVAL but
177// reports a read error and exits 2 on ENOSYS. Replaying an older stream under
178// the new errno could change guest control flow and event consumption, although
179// no event shape changed.
180// 0x121 -> 0x122: Detcore numbers raw mount IDs in the order the guest first
181// observes them through mountinfo or fdinfo, instead of by row position in the
182// run's starting mountinfo. Metadata carries that order as
183// `mount_id_assignment_order`, replacing `fdinfo_unlisted_mount_ids`, and
184// replay numbers every raw ID from it. An older recording's metadata cannot
185// rebuild the mapping its guest saw, so replaying it could change the mount IDs
186// the guest reads and its control flow.
187// 0x122 -> 0x123: Detcore's inode pool starts at 9000 instead of 1 and every
188// numbering request consumes a number, so the deterministic inode numbers
189// differ (https://github.com/rrnewton/hermit/issues/2897). Even with
190// virtualize_metadata off, as record/replay runs, the procfs sanitizer renders
191// pool numbers into /proc/*/fdinfo `ino:` lines and /proc/*/maps and smaps
192// inode columns over the recorded raw bytes, during recording and again during
193// replay. An older recording replayed under the new numbering could show the
194// guest different bytes, although no event shape changed.
195// 0x123 -> 0x124: accept and accept4 record an `Accept` event, and bind, listen
196// and shutdown record a `Return` event, instead of running live during replay
197// (https://github.com/rrnewton/hermit/issues/3864). An older recording has no
198// events for these calls, so this replayer would consume another call's event.
199// 0x124 -> 0x125: a blocking accept on a listener the container created runs in
200// the caller's turn (https://github.com/rrnewton/hermit/issues/3880). It
201// records one `Accept` event per nonblocking attempt, where an older recording
202// has a single `Accept` event for the backgrounded call. (Its timeout comes
203// from Detcore's model of `setsockopt`, not from a recorded event.) Connections accepted under record
204// are no longer made nonblocking. An older recording would hand this replayer
205// the wrong number of events. A recording also carries a `rejoins` file, the
206// turns at which backgrounded calls rejoined the run queue, which replay
207// requires.
208// 0x125 -> 0x126: in the precise futex mode a FUTEX_WAKE that wakes fewer
209// waiters than are waiting takes the longest waiters first, as Linux does,
210// instead of the most recent ones, and a FUTEX_WAKE_BITSET leaves the waiters
211// it skips in arrival order (https://github.com/rrnewton/hermit/issues/3917).
212// Futex waits and wakes are not recorded events; replay recomputes which thread
213// each wake takes, so an older recording replayed under the new order could run
214// a different schedule, although no event shape changed. Schedule and
215// preemption files written by `--record-preemptions-to` carry no version and
216// are likewise tied to the old order.
217// 0x126 -> 0x127: a vfork barrier ends at the child's release edge (its exec
218// or `Exit` grant) whether or not the parent's death has been seen. With a
219// live parent, the scheduler then commits no turn until the parent's
220// continuation is posted, where the child used to keep running alone for a
221// host-timed number of turns (https://github.com/rrnewton/hermit/issues/3984).
222// Turn selection is not recorded; replay recomputes it, so an older recording
223// containing a vfork replayed under the new rule could run a different
224// schedule, although no event shape changed.
225// 0x127 -> 0x128: on ptrace, `prctl(PR_SET_CHILD_SUBREAPER)` and
226// `PR_GET_CHILD_SUBREAPER` run live in record and replay alike instead of
227// failing with ENOSYS, and the scheduler re-parents orphans to a child
228// subreaper (https://github.com/rrnewton/hermit/issues/3997). An older
229// recording saw ENOSYS for both calls; this replayer would run them and could
230// take another branch and a different schedule, although no event shape
231// changed.
232// 0x128 -> 0x129: record and replay set
233// `backend_supports_blocked_wait_signal_interruption`, so the scheduler models
234// signal targets as `hermit run` does on ptrace
235// (https://github.com/rrnewton/hermit/issues/3963). A thread that a committed
236// signal wakes out of a backgrounded call rejoins at the release barrier, a
237// precise FUTEX_WAIT or an rt_sigtimedwait ends only for a signal that would end
238// it on Linux, and an emulated pause or nanosleep ends for another thread's
239// signal. (poll, epoll_wait, select and pselect6 are logged background calls
240// here, which the kernel itself ends.) Replay recomputes all of these, so an
241// older recording replayed here could run a different schedule, although no
242// event shape changed.
243// 0x129 -> 0x12a: a SIGCHLD the scheduler sends at a commit point (a child's
244// child-exit timer, or a POSIX timer) ends a precise FUTEX_WAIT that catches
245// it, as on Linux, where it was held until the call returned
246// (https://github.com/rrnewton/hermit/issues/4005). Replay recomputes precise
247// futex results, so an older recording replayed here could take the other
248// branch, although no event shape changed (Codex review of
249// https://github.com/rrnewton/hermit/pull/4039).
250// 0x12a -> 0x12b: on ptrace, a clone without CLONE_THREAD and with a
251// non-SIGCHLD exit signal is its own process to the Tool, with its own pid and
252// its kernel parent (https://github.com/rrnewton/hermit/issues/4012). Detcore
253// recomputes calls that name that process (getpid-based prlimit, its exit and
254// its parent's notification) from it, so an older recording replayed here
255// could take another branch, although no event shape changed.
256// 0x12b -> 0x12c: a precise FUTEX_WAIT woken for a signal that is no longer
257// pending for it re-reads its word and answers EAGAIN if the word changed
258// (EFAULT if unreadable), where it answered 0 as a wakeup; Linux's woken waiter
259// reaches the same EAGAIN through -ERESTARTSYS and the restarted wait. A signal
260// still pending for it is answered before the word is compared
261// (https://github.com/rrnewton/hermit/issues/4033). Replay recomputes
262// precise futex results, so an older recording replayed here could see another
263// result and take another branch, although no event shape changed.
264// 0x12c -> 0x12d: a precise FUTEX_WAIT or FUTEX_WAIT_BITSET checks its timeout
265// and bitset before the word, and reads the word with user-mode permissions, as
266// Linux's `futex_wait_setup` does: EFAULT for an unmapped or PROT_NONE word,
267// where the tracer's read gave EIO or compared a PROT_NONE word's value
268// (https://github.com/rrnewton/hermit/issues/4030). Replay recomputes precise
269// futex results, so an older recording replayed here could see another errno
270// and take another branch, although no event shape changed (Codex review of
271// https://github.com/rrnewton/hermit/pull/4061).
272// 0x12d -> 0x12e: a pidfd_send_signal to a process with one live thread tells
273// the scheduler the signal is pending for that thread, as kill does, so a
274// receiver parked in a blocking call is woken to take it
275// (https://github.com/rrnewton/hermit/issues/4099). Replay recomputes
276// the schedule, so an older recording replayed here could be scheduled
277// differently, although no event shape changed.
278// 0x12e -> 0x12f: a kill to a zombie (exited, its parent can still wait for
279// it) answers 0, as Linux's kill_pid_info does, where it answered ESRCH; a
280// kill(pid, 0) to an exited process answers from the same model; and an
281// rt_sigaction(SIGCHLD) tells the scheduler whether the process now reaps its
282// children automatically (https://github.com/rrnewton/hermit/issues/4091).
283// Replay recomputes these answers and the schedule, so an older recording
284// replayed here could see another result and take another branch, although
285// no event shape changed.
286// 0x12f -> 0x130: `epoll_pwait` is recorded with the event `epoll_wait`
287// records, and replay serves it from the recording. It used to run live in
288// record and replay alike, so an older recording holds no event for it and this
289// replayer would desynchronize at the first one.
290// 0x130 -> 0x131: an rt_sigqueueinfo to a zombie is forwarded to the kernel,
291// which checks the siginfo and then finds the zombie (0), where it answered
292// ESRCH (https://github.com/rrnewton/hermit/issues/4091). Replay recomputes
293// the answer, so an older recording replayed here could see another result
294// and take another branch, although no event shape changed.
295// 0x131 -> 0x132: a process-directed signal naming a live non-leader thread's
296// id goes to that thread's process, as Linux's kill_pid_info does, where it
297// answered ESRCH (https://github.com/rrnewton/hermit/issues/4094). Replay
298// recomputes the answer, so an older recording replayed here could see another
299// result and take another branch, although no event shape changed.
300// 0x132 -> 0x133: record readmits a finished background call while the only
301// runnable work queued is threads that yielded and pollers, where it used to
302// wait for every yielder to stop (https://github.com/rrnewton/hermit/issues/4092).
303// Replay follows the logged readmission turn only once its gate opens, and an
304// older replayer's gate stays shut in that state, so it could not consume the
305// readmission: it would refuse, or hang behind a yielder that never stops
306// (Codex review of https://github.com/rrnewton/hermit/pull/4120).
307// 0x133 -> 0x134:
308// a masked or zero-timeout ppoll on a stack with no scratch below its red zone
309// stages its private timeout and mask in the red zone, where it returned EFAULT
310// and recorded nothing, and a masked record/replay pselect6 that replay could
311// not deliver an interruption of is refused
312// (https://github.com/rrnewton/hermit/issues/4113,
313// https://github.com/rrnewton/hermit/issues/4112). An older recording of such a
314// ppoll holds no event for the call, so this replayer would desynchronize at it
315// (Claude review of https://github.com/rrnewton/hermit/pull/4127).
316// 0x134 -> 0x135: an rt_sigqueueinfo to a gone process makes the kernel check
317// its siginfo (EFAULT, E2BIG, EPERM) before answering ESRCH, where Detcore
318// answered ESRCH first; an rt_sigqueueinfo existence check (signal 0) answers
319// from the same exit model (https://github.com/rrnewton/hermit/issues/4124).
320// Replay recomputes the answer, so an older recording replayed here could see
321// another result and take another branch, although no event shape changed.
322// 0x135 -> 0x136: on ptrace, a guest-sent SIGKILL retires its victims at the
323// sending turn instead of at their host-timed deregistration
324// (https://github.com/rrnewton/hermit/issues/3994). Turn and wait selection
325// are not recorded; replay recomputes them, so an older recording replayed
326// under the new rule could run a different schedule. The metadata also gains
327// `replay_refused`, which an older replayer would not check.
328// 0x136 -> 0x137: `epoll_pwait2` is recorded with the event `epoll_wait`
329// records, and replay serves it from the recording; it ran live before
330// (https://github.com/rrnewton/hermit/issues/4088).
331// 0x137 -> 0x138: a guest send of a default-stop signal records SIGHUP and
332// SIGCONT as host-timed for every process, which an orphaned process group
333// can receive at an exit's physical moment
334// (https://github.com/rrnewton/hermit/issues/4111), so no gated wait ends for
335// them afterwards. Replay recomputes the schedule, so an older recording
336// replayed here could see such a wait end, although no event shape changed.
337// Record and replay refuse the newly admitted signal to the sender's own
338// process (https://github.com/rrnewton/hermit/issues/4034), so that change
339// alters no recording.
340// 0x138 -> 0x139: pidfd_send_signal with a PIDFD_SIGNAL_THREAD or
341// PIDFD_SIGNAL_THREAD_GROUP flag, or through a /proc/<pid> directory, is
342// forwarded, where Detcore answered EINVAL or EBADF without an event
343// (https://github.com/rrnewton/hermit/issues/4108). An older recording holds no
344// event for such a call, so this replayer would desynchronize at it.
345// 0x13b -> 0x13c: pidfd_send_signal through the PIDFD_SELF_THREAD or
346// PIDFD_SELF_THREAD_GROUP sentinel is forwarded, where Detcore answered EBADF
347// without an event (https://github.com/rrnewton/hermit/issues/4147). An older
348// recording holds no event for such a call, so this replayer would
349// desynchronize at it.
350// 0x13c -> 0x13d: timer_create with SIGEV_THREAD_ID answers EINVAL for a
351// thread outside the caller's process (and for an invalid notify value, where
352// it answered ENOSYS), and the timer's expirations go to that thread alone,
353// dropped once it has exited, where they went to the whole process
354// (https://github.com/rrnewton/hermit/issues/4164). Replay recomputes both, so
355// an older recording replayed here could see different answers and deliveries.
356// 0x13d -> 0x13e: a vfork child that Detcore backgrounded, and that the vfork
357// gate waits for while every queued thread is excluded, is readmitted as soon
358// as its call finishes, without a rejoin entry: before it, no turn can commit
359// (https://github.com/rrnewton/hermit/issues/4163). An older recorder spun
360// forever in that state, and replay recomputes the schedule, so an older
361// recording replayed here could see the readmission where its recorder did
362// not.
363// 0x13e -> 0x13f: a guest in a nested PID namespace has its pids translated
364// (https://github.com/rrnewton/hermit/issues/4155,
365// https://github.com/rrnewton/hermit/issues/4090): kill and its relatives
366// deliver where they answered ESRCH, fork returns the nested pid, waits reap
367// where they answered ECHILD, the init's own default signals are dropped, and
368// orphans go to the nested init. Replay recomputes these, so an older
369// recording of such a guest could diverge.
370// 0x13f -> 0x140: a record/replay pselect6 that may wait reads its temporary
371// mask at the call's entry, where Linux copies it, and recording waits on a
372// private copy; replay read it after the grant
373// (https://github.com/rrnewton/hermit/issues/4095). An older recording whose
374// sibling rewrote the mask between the two can replay differently here.
375// 0x140 -> 0x141: sched_getaffinity accepts any length that is a nonzero
376// multiple of sizeof(long), as Linux does for one CPU, and copies and returns
377// min(len, 16), where it answered EINVAL below 16 bytes
378// (https://github.com/rrnewton/hermit/issues/4160). Replay answers the call
379// itself, so an older recording that saw EINVAL would see success here.
380// 0x141 -> 0x142: a signal that another task sends ends a restartable call
381// that Detcore polls internally (a blocking pipe read or write, readv, recv,
382// send, accept4, connect, and the legacy wait4 polling) when the kernel would
383// deliver it, where the poll ignored it and retried
384// (https://github.com/rrnewton/hermit/issues/4187). The recorder logs each
385// polled EAGAIN but not the scheduler's signaled answer, so recordings made
386// before and after this change do not replay on each other's replayer.
387// 0x142 -> 0x143: epoll_ctl is recorded, and replay answers it from the
388// recording (https://github.com/rrnewton/hermit/issues/31). An older recording
389// has no event for it.
390// 0x143 -> 0x144 (https://github.com/rrnewton/hermit/pull/4131):
391// a child-exit SIGCHLD the scheduler sends ends an emulated pause or nanosleep
392// only when the thread's mask leaves it unblocked and it is caught or
393// default-fatal, and a still-queued sleep is woken for it
394// (https://github.com/rrnewton/hermit/issues/4126). Replay recomputes such a
395// sleep's result, so an older recording of a blocked or default SIGCHLD during
396// a nanosleep holds the EINTR it used to return, and this replayer would answer
397// 0: a successful replay with different output (Codex review of
398// https://github.com/rrnewton/hermit/pull/4131).
399// 0x144 -> 0x145: an fcntl that writes its result through its argument
400// (F_GETOWN_EX, which glibc uses for F_GETOWN; F_GETLK, F_GETLK64,
401// F_OFD_GETLK; the write-hint queries) records the bytes it wrote, and replay
402// writes them back (https://github.com/rrnewton/hermit/issues/2289). An older
403// recording has no such event.
404// 0x145 -> 0x146: a successful exec takes back the POSIX timer signals
405// Detcore sent that are still queued, as Linux discards them
406// (flush_itimer_signals; https://github.com/rrnewton/hermit/issues/4184),
407// where they survived the exec and reached the new image. Replay recomputes
408// this, so an older recording replayed here could see a delivery its recorder
409// saw and this replayer drops.
410// 0x146 -> 0x147: while a vfork barrier stands, the scheduler selects other
411// runnable threads when no barrier child is queued to run a turn and none is in
412// the background (each is blocked on another thread or polling a call that is
413// not ready) (https://github.com/rrnewton/hermit/issues/4194). A polling child
414// used to run alone; replay recomputes the schedule, so an older recording of a
415// vfork child that polled for a host event, with other threads runnable, could
416// replay differently. A backgrounded child is still waited for, as before.
417// 0x147 -> 0x148: get_mempolicy answers as a one-node Linux machine
418// (https://github.com/rrnewton/hermit/issues/4214): MPOL_F_MEMS_ALLOWED fills
419// the node mask with node 0 and the default policy's mask is written empty,
420// where Detcore left the guest's buffer unwritten, and flag combinations Linux
421// refuses are EINVAL, where Detcore answered 0. Replay answers the call
422// itself, so an older recording of such a call would replay with different
423// answers.
424// 0x148 -> 0x149: when the guest's CPUID comes from Detcore's table,
425// /proc/cpuinfo describes that virtual CPU, generated from the table, where it
426// showed the host's model, flags and caches
427// (https://github.com/rrnewton/hermit/issues/4161). Record virtualizes CPUID,
428// and Detcore renders procfs over the recorded bytes during recording and
429// again during replay, so an older recording would replay with different bytes.
430// 0x149 -> 0x14a: the procfs files that describe the kernel and its fixed
431// limits (/proc/version, /proc/cmdline and 12 kernel and vm sysctls)
432// are procfs files whose contents Detcore fixes from its machine description
433// (https://github.com/rrnewton/hermit/issues/4266), where they were ordinary
434// files whose host bytes were recorded as read. Replay serves a classified
435// procfs file itself, so an older recording of a read of one would replay
436// with different events.
437// 0x14a -> 0x14b: a guest's thread-directed SIGCHLD (tgkill, pthread_kill,
438// pthread_sigqueue) that the sender's turn recorded ends a precise futex wait, before or after the wait
439// parks, when the waiter's mask leaves it unblocked and it is caught
440// (https://github.com/rrnewton/hermit/issues/4132). The same copy has ended an
441// emulated pause or nanosleep since
442// https://github.com/rrnewton/hermit/pull/4177, which changed those results
443// with no bump of its own; this one covers both. Replay recomputes both
444// results, so an older recording of such a send would replay with the wait or
445// the sleep ended early: a successful replay with different output.
446// 0x14b -> 0x14c: under record, a vfork child whose call runs in the
447// background no longer stops every other thread; it is readmitted as soon as
448// the call finishes and the turn is written to the rejoin log, which replay
449// follows (https://github.com/rrnewton/hermit/issues/4211). An older recording
450// has no rejoin entry for such a readmission, so this replay could not follow
451// it.
452// 0x14c -> 0x14d: the kernel's tables (/proc/interrupts, softirqs, zoneinfo,
453// meminfo, modules and 16 others) are fixed files that Detcore renders from
454// its machine description with no kernel read
455// (https://github.com/rrnewton/hermit/issues/4266), where Detcore sanitized
456// the host's file and kept its shape: its interrupt names, zones and one
457// column per host CPU. And every open whose spelling Detcore does not
458// classify (nearly every open outside /proc and /sys) now records a readlink
459// of the descriptor, which replay answers, so both runs classify it alike. An
460// older recording would replay with different bytes and events.
461// 0x14d -> 0x14e: a child-exit SIGCHLD the scheduler sends a parked precise
462// futex waiter is placed at that commit point, so the waiter's woken turn is
463// granted ahead of a runnable sibling rather than deferred behind it, and the
464// waiter, not the sibling, takes the signal and returns EINTR
465// (https://github.com/rrnewton/hermit/issues/4304). Replay recomputes the
466// schedule and futex results, so an older recording of such an exit would
467// replay with the handler in another thread and a different futex result.
468// 0x14e -> 0x14f: a timer's process-directed signal (alarm, an itimer, a
469// POSIX timer) is sent to a thread that does not block it, not to the thread
470// that armed it or the one chaos drew when that thread blocks it, and that
471// thread is the one woken (https://github.com/rrnewton/hermit/issues/4320).
472// Replay recomputes the send, so an older recording of a timer whose arming
473// thread blocked its signal would replay with another thread woken. And a
474// background rt_sigsuspend that the host reports as ERESTARTSYS returns
475// ERESTARTNOHAND, the only result Linux's rt_sigsuspend has, so an older
476// recording of one would replay with a different result and restart.
477pub(crate) const RECORD_VERSION: RecordVersion = RecordVersion(0x14f);
478
479/// The highest RECORD_VERSION this project has ever shipped.
480///
481/// RECORD_VERSION must never move BACKWARD onto it. This is a COMPILE-TIME
482/// assertion rather than a test on purpose: it is decidable from two constants,
483/// so it should break the build rather than a test run, and it cannot be
484/// skipped, filtered or left unrun.
485///
486/// WHY IT EXISTS AT ALL. The rejection set in `record_version_requires_an_exact_match`
487/// used to be a list of specific versions, and `!compatible_with(0x10a)` was
488/// catching a backward move BY ACCIDENT. Replacing that list with a window derived
489/// from RECORD_VERSION fixes its silent narrowing but cannot catch a regression,
490/// because a derived window re-derives from whatever the constant currently says.
491/// Dropping the list without this floor would have traded a stale check for a
492/// weaker one.
493///
494/// The failure it guards is near, not hypothetical: a long-stale branch that bumped
495/// 0x109 -> 0x10a while main advanced to 0x10e regresses the constant the moment its
496/// conflict is resolved by taking the branch side. The build would then stamp the
497/// current schema with a label an older reader already claims, and the exact-match
498/// gate would accept a stream whose shape it does not know -- the desynchronization
499/// the version exists to prevent.
500///
501/// RAISE THIS IN THE SAME COMMIT THAT RAISES RECORD_VERSION.
502const HIGHEST_SHIPPED_RECORD_VERSION: u32 = 0x14f;
503
504const _: () = assert!(
505    RECORD_VERSION.0 >= HIGHEST_SHIPPED_RECORD_VERSION,
506    "RECORD_VERSION is BELOW HIGHEST_SHIPPED_RECORD_VERSION. A recording made by this \
507     build would carry a label an older reader already claims. If this fired during a \
508     rebase, the version constant was resolved BACKWARD -- merge it forward."
509);

560    /// Whether the recording ran in an isolated network namespace with only

570impl Metadata {
571    /// Creates a new metadata object, populating it with information about a
572    /// command.
573    pub fn new(command: &Command) -> Result<Self, Error> {
574        let exe = command.find_program()?;
575
576        let program = command.get_program().to_string_lossy().into_owned();
577        let arg0 = command.get_arg0().to_string_lossy().into_owned();
578
579        let args = command
580            .get_args()
581            .map(|arg| arg.to_string_lossy().into_owned())
582            .collect();
583
584        let envs = command
585            .get_captured_envs()
586            .into_iter()
587            .map(|(k, v)| {
588                (
589                    k.to_string_lossy().into_owned(),
590                    v.to_string_lossy().into_owned(),
591                )
592            })
593            .collect();
594
595        let current_dir = command
596            .get_current_dir()
597            .map_or_else(|| env::current_dir().unwrap(), ToOwned::to_owned);
598
599        let hostname = command
600            .get_hostname()
601            .map(|s| s.to_string_lossy().into_owned());
602        let domainname = command
603            .get_domainname()
604            .map(|s| s.to_string_lossy().into_owned());
605
606        Ok(Self {
607            exe,
608            program,
609            arg0,
610            args,
611            current_dir,
612            hostname,
613            domainname,
614            envs,
615            replay_refused: None,
616            version: RECORD_VERSION,
617            proc_readonly: None,
618            mountinfo_root_rewrites: Vec::new(),
619            mountinfo_mount_ids: Vec::new(),
620            mountinfo_mount_ids_captured: false,
621            mount_id_assignment_order: Vec::new(),
622            local_networking: None,
623        })
624    }
625
626    /// Reads the metadata of the recording stored in `dir`.
627    pub fn load(dir: &Path) -> Result<Self, Error> {
628        let metadata_path = dir.join(METADATA_NAME);
629        serde_json::from_reader(
630            fs::File::open(&metadata_path)
631                .with_context(|| format!("Failed to open {:?}", metadata_path))?,
632        )
633        .with_context(|| format!("Failed to parse {:?}", metadata_path))
634    }
635
636    /// Constructs a command from the metadata.
637    pub fn command(&self) -> Command {
638        // NOTE: We bypass the normal $PATH search here by passing in the
639        // absolute path to the program directly.
640        let mut command = Command::new(&self.exe);
641        command.arg0(&self.arg0);
642        command.args(&self.args);
643        command.env_clear();
644        command.envs(&self.envs);
645        command.current_dir(&self.current_dir);
646
647        if let Some(hostname) = &self.hostname {
648            command.hostname(hostname);
649        }
650
651        if let Some(domainname) = &self.domainname {
652            command.domainname(domainname);
653        }
654
655        command
656    }

659pub fn record_or_replay_config(data: &Path) -> detcore::Config {
660    // NOTE: Record and replay should use the exact same Detcore configuration.
661    // Callers add the completed producer namespace's mountinfo order and
662    // mount-ID assignment order after this common base is built, so replay
663    // uses recording-time raw IDs rather than IDs from its fresh container.
664    //
665    // WHY THIS IS NOT `hermit run --strict`, WRITTEN HERE ON PURPOSE.
666    //
667    // `virtualize_time: false` below is DELIBERATE, and the rationale used to live only
668    // in the separate dev-hermit workspace -- not in this repository, beside the code it
669    // governs. The cost of that was measured: three agents in one night read this line,
670    // searched this repo's source, git log, docs/ and issues, found nothing, and could
671    // not tell a design decision from a determinism bug; two coordinators then spent
672    // hours treating it as a candidate defect. A decision recorded in a different
673    // repository from the code it governs is, in practice, undocumented. Hence this
674    // comment. See rrnewton/hermit#2295.
675    //
676    // WHAT RECORD/REPLAY ACTUALLY GUARANTEES. Replay re-executes a recording against the
677    // recorded syscall data, so what must be reproducible is THIS recording's replay --
678    // not agreement between two independent recordings. Time is therefore left real: the
679    // recording captures what the guest actually observed, and replay returns those
680    // recorded values. `hermit record start --verify` records once, replays that
681    // recording, and compares the two; its success message says exactly that ("replay
682    // matched recording") and does not claim more.
683    //
684    // WHAT IT DOES NOT GUARANTEE, which is the part that misleads readers. Because time
685    // is not virtualized, two INDEPENDENT recordings of the same program observe
686    // different clock values. Demonstrated: `hermit run -- date` twice returns the
687    // identical virtual epoch, while `hermit record start -- date` twice returns real
688    // wall-clock times seconds apart. Replay fidelity says nothing about that, and
689    // the focused `independent_mountinfo_recordings_are_canonical` test compares
690    // two independent mountinfo recordings after replacing exactly field 3, the
691    // major:minor device column. With `virtualize_metadata: false`, Linux may
692    // legitimately allocate a different anonymous-block-device minor for the
693    // private procfs mount in each container. That test still compares mount ID,
694    // parent ID, root, mountpoint, options, optional fields, separator,
695    // filesystem type, source, and superblock options byte-for-byte. It does not
696    // establish general cross-recording determinism, and a green `--verify`
697    // remains only a replay-fidelity result.
698    //
699    // This configuration differs from `hermit run --strict` on four of the five
700    // properties that define it (see run.rs: only `sequentialize_threads` matches).
701    // Any claim that recording is "strict" in that sense is wrong; the `--strict` flag
702    // on `hermit record` is accepted for command-line compatibility, and its only effect
703    // is to refuse a host whose retired-branch counter is inexact
704    // (https://github.com/rrnewton/hermit/issues/3810).

712        // backend callback. The tracer owns process-tree cleanup on that error.

718        runs_post_fork: default_config.runs_post_fork,
719        // Record/replay keeps a partial Detcore subscription. Complete coverage
720        // of the Determinized classification begins in v0x10a; madvise policy
721        // semantics begin in v0x102.
722        passthru_opt: true,
723        deterministic_io: false,
724        virtualize_time: crate::RECORD_REPLAY_VIRTUALIZES_TIME,
725        virtualize_metadata: false,
726        mountinfo_root_rewrites: Vec::new(),
727        mountinfo_device_rewrites: Vec::new(),
728        mountinfo_mount_ids: Vec::new(),
729        mountinfo_mount_ids_captured: false,
730        mount_id_assignment_order: Vec::new(),
731        virtualize_cpuid: true,
732        // Record and replay run under the ptrace backend.
733        backend: <reverie_ptrace::PtraceBackend as reverie::Backend>::capabilities(),
734        // As `hermit run` sets it for ptrace (`prepare_backend_config` in
735        // lib.rs). With it off, the scheduler did not model signal targets, so
736        // a thread asleep in a backgrounded rt_sigsuspend that a child-exit
737        // SIGCHLD woke was not held at the release barrier: the scheduler could
738        // pop the next timer, or report a terminal deadlock, before the thread's

745        // for the terminal signals a guest sends itself, so a caught SIGINT
746        // still ends a FUTEX_WAIT or rt_sigtimedwait in every recording; a

820/// Whether this host can arm Reverie's ptrace timer for a record or replay:
821/// working perf counters AND a PMU profile for its CPU. Without a profile,
822/// Reverie gives no task a timer, so a timeslice would be configured and never
823/// delivered.
824fn record_timer_support() -> Result<(), String> {
825    timer_support_from(
826        reverie_ptrace::is_perf_supported(),
827        reverie_ptrace::host_pmu_profile(),
828    )
829}

831/// [`record_timer_support`] from what the host answered: whether perf works,
832/// and whether Reverie has a PMU profile for its CPU.
833fn timer_support_from(
834    perf_supported: bool,
835    profile: Result<(), reverie_ptrace::PmuValidationError>,
836) -> Result<(), String> {
837    if !perf_supported {
838        return Err("hardware perf counters are not supported on this machine".to_owned());
839    }
840    profile.map_err(|error| error.to_string())
841}

843/// Turn off `config`'s timeslice, which this host cannot deliver (`reason`).
844fn disable_timeslice_without_a_timer(config: &mut detcore::Config, reason: &str) {
845    if config.max_timeslice.is_some() {
846        tracing::warn!("{reason}; Records/Replays run without a timeslice and may randomly fail!");
847        config.max_timeslice = None;
848    }

946        //
947        // This assertion used to be a list of specific versions -- 0x10a, 0x10c,
948        // 0x105, 0x110. A list SILENTLY NARROWS every time RECORD_VERSION
949        // advances: the named values drift away from the boundary that matters,
950        // and the test keeps passing while checking less and less. It cannot
951        // fail for the reason its name gives once the value has moved past the
952        // range someone happened to write down.
953        //
954        // `compatible_with` is exact equality, so the property to assert is
955        // "every OTHER version is refused". Re-deriving the cases from
956        // RECORD_VERSION itself means the window travels with the constant and

958        let current = RECORD_VERSION.0;
959        for delta in 1..=16u32 {

961            assert!(
962                !RECORD_VERSION.compatible_with(&older),
963                "recorder at {current:#x} must refuse a recording made at {:#x}",
964                older.0
965            );
966            let newer = RecordVersion(current + delta);
967            assert!(
968                !RECORD_VERSION.compatible_with(&newer),
969                "recorder at {current:#x} must refuse a recording made at {:#x}",
970                newer.0
